# Backend conventions

- **Layout.** `src/common` holds infrastructure (access, ai, audit, database, health, i18n, mail, protection, rich-text, robots,
  secrets, storage), global modules injected everywhere; `src/modules` holds features, each a service plus thin controllers:
  `newsroom` (news, sections, tags, media, translation, front page, scheduler, public queries), `ai-writer`, `site` (identity,
  themes, legal texts, contact), `team` (accounts, roles, profile, audit trail), `settings`, `dashboard`, `public`.
- **Controllers** of the panel are `@Controller('panel/...')` + `@PanelController()` (session guard, permission guard, private
  answers, error filter) and declare `@RequirePermissions(...)` on every handler (an empty list admits any signed-in account).
  Public controllers live under `public/...` and read published content only.
- **Services** receive the `Actor` and call `requirePermission` again; item-level rules (own item, status) live in the service.
- **Validation:** class-validator DTOs with `forbidNonWhitelisted`; bilingual fields are normalized by `i18nString`;
  rich text by the article grammar. DTO instances carry every declared field (absent ones `undefined`): merge only defined values.
- **Errors** carry a stable `code` the interface translates (`news_conflict`, `news_incomplete`, `media_in_use`, `ai_unconfigured`…).
- **Audit:** `audit(manager, { actorId, action, resourceType, resourceId, metadata })` inside the same transaction as the change.
- **Routes reference:** `docs/architecture/api-routes.md`, generated by `node scripts/api-routes.mjs`.
